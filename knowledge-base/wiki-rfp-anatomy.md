# RFP Anatomy

When to use: Extract all requirements from the RFP before writing a single word of the application.

---

## Key Sections to Extract
| Section | What to pull |
|---|---|
| Program Overview | Funder priorities, what they fund/don't fund |
| Eligibility Requirements | Org type, geography, revenue limits, prior funding restrictions |
| Funding Details | Award amount, project period, matching fund requirements |
| Application Requirements | Required sections, word/page limits per section, file format |
| Evaluation Criteria | Criterion names, point weights, what earns full marks |
| Deadline & Submission | Date, time, time zone, portal or email |
| Reporting Requirements | Mid-term/final reports, outcome metrics required |

## Evaluation Criteria
- If explicit: record each criterion name exactly as the funder wrote it + point weight
- If implicit: infer from program overview; label entire table `[INFERRED — not stated in RFP]`
- These criteria feed directly into [[wiki-alignment-methodology]]

## Eligibility — Mandatory STOP
Before any drafting: confirm every eligibility requirement is met from the org profile.
If any requirement cannot be confirmed → halt and ask the user before proceeding.
Common traps: requirements buried in appendices, prior recipient restrictions, revenue caps.

## Word & Page Limits
- Hard constraints, not targets
- Flag any section at 90%+ of limit
- Flag any section over limit as `[⚠ OVER LIMIT — must cut before submission]`

## Common Traps
- Eligibility buried in schedules/appendices — read the whole document
- Conflicting limits between body and attached template — use the template
- Deadlines in a different time zone than the applicant
